LESSON 01 / 16
Diagnose incorrect or inconsistent LLM outputs
Separate request reproducibility, factual accuracy, nondeterministic sampling, prompt state, and model drift.
A Interviewer questions
  1. A customer receives two different answers to the same prompt. What exact evidence do you collect before debugging?
  2. How would you isolate decoding stochasticity from provider changes or retrieval nondeterminism?
  3. How do you distinguish a model failure from a prompt-template or tool-output regression?
B Deep technical explanation
Mechanism and data flow
Model output is conditional on the COMPLETE effective request: system/developer messages, chat history, retrieved text, tools, model snapshot, sampler, seed (when supported), and inference backend. Capture redacted request identifiers, model and prompt versions, tool calls, sampled tokens where permitted, outputs and trace timing. Reproduce a golden input with retrieval snapshot and fixed parameter configuration; minimize the failing case. Classify error as knowledge/retrieval gap, reasoning, instruction hierarchy conflict, formatting, unsafe tool use or evaluation artifact. Compare failing vs passing traces one variable at a time. Temperature zero or a seed may reduce variance, but GPU kernels, tie-breaking, batching and API changes can still prevent bitwise reproducibility.
Mathematics and invariants
For N independently sampled responses: empirical failure rate p̂ = failures/N. For regression contrast use Δ = p̂_new − p̂_base with confidence intervals, ideally on paired prompt cases; a single divergent output cannot establish a degradation.
Architecture and alternatives
Start with deterministic preprocessing and stable retrieval + prompts before fine-tuning. Escalate to better model, tool verification or SFT only when failure slices prove simpler controls insufficient.
Implementation and instrumentation
Store privacy-safe trace IDs, prompt hash, effective template hash, model checkpoint, sampler config, retrieval document IDs/versions, token counts and structured evaluator results. Use stratified test cases with human adjudication.
Latency, memory, cost and scaling
Repeatability requires data/version pinning and an eval budget; exhaustive logging raises storage and PII exposure risk. Sample traces and redact sensitive inputs while retaining correlation IDs.
Failure modes and traps
Avoid claiming all nondeterminism is temperature; provider routing, safety filters, retrieval indexes, compaction, lossy OCR and schema changes can alter effective context. Never debug from screenshots alone.
C Interview-ready spoken answer
“I first lock down the effective input and model configuration, then replay paired failing and passing traces. I separate stochastic sampling from deterministic pipeline changes and split errors by retrieval, reasoning, instruction following and output parsing. I measure failure rates on a held-out slice and ship a fix only if its quality and latency trade-offs hold in canary.”
D Follow-up pressure test
  1. Will temperature=0 guarantee identical tokens on two GPUs?
  2. What if the retrieved chunks differ but the query string is identical?
  3. How do you prove the new prompt fixed an issue instead of overfitting five examples?
E Production incident → action → validation
Constraint and investigation: A support bot contradicts itself after a silent prompt deployment. First inspect version tags and canary vs control responses. Reconstruct same user-visible question with frozen documents; then revert or amend prompt based on a paired eval rather than anecdotal feedback.
Instrument, evaluate and release criteria: Define a baseline, task-specific factual/correctness score, regression-set pass rate, p95 response time and rollback rule; no fabricated improvement percentages.
F Interview takeaways
  • Effective context defines what the model actually sees.
  • Classify and trace errors before choosing a fix.
  • Paired, version-pinned evals beat anecdotal examples.
LESSON 02 / 16
Debug structured-output failures and malformed JSON
Differentiate syntactic JSON, schema compliance, business semantics, and partial streamed output.
A Interviewer questions
  1. Why can a JSON-mode response parse successfully but still fail downstream?
  2. How do constrained decoding and schema validation differ?
  3. What does your retry strategy do when a tool call has already caused a side effect?
B Deep technical explanation
Mechanism and data flow
Structured output has multiple gates: (1) transport and streamed frame completeness, (2) valid JSON syntax, (3) schema-level types, required fields, enums, ranges, and extra-field policy, (4) semantic invariants such as sum of marks or consistent IDs. Prefer model-native constrained decoding for a supported JSON Schema subset where available, followed by application-side validation. Streaming JSON is often incomplete until the finish event; buffer or use incremental parsers that track object boundaries. A refusal or truncation is not the same as a malformed payload. On failure, return a typed error or repair only with budgeted, non-side-effecting retries. Persist idempotency tokens before tool execution and never replay a completed side effect merely to fix serialization.
Mathematics and invariants
End-to-end structured success = valid_transport ∧ valid_syntax ∧ valid_schema ∧ valid_semantics. Track conditional failure counts for each gate, not a single parse-error bucket.
Architecture and alternatives
Schema-first generation is stronger than prompting “return JSON”; locally validated parser retries are a fallback if provider lacks constrained decoding. For safety-critical commands, no free-form auto-repair without approval.
Implementation and instrumentation
Illustrative schema: {status: enum["ok","abstain"], answer: string|null, evidence_ids: string[]}; reject unknown keys, validate evidence IDs against an authorized list, and enforce status="abstain" ⇒ answer=null. For Python use json.loads plus explicit schema/domain validators.
Latency, memory, cost and scaling
Retries add latency and token cost; bad retry design causes retry storms. Schema compilation and constrained decoding can have startup/complexity costs. Monitor parse-fail rate and number of repair attempts.
Failure modes and traps
A syntactically valid but wrong ID is still unsafe. Streaming chunks are not independent complete JSON documents. Supported JSON Schema features depend on model/provider; do not promise arbitrary regular expressions or complex constraints.
C Interview-ready spoken answer
“I divide structured output into transport, syntax, schema, and semantic validity. I use native constrained decoding where supported, then server-side validation against permissions and invariants. I treat refusal/truncation separately and use bounded retries only for idempotent generation—not for side-effecting tools.”
D Follow-up pressure test
  1. How do you distinguish a model refusal from empty schema fields?
  2. What happens if a JSON stream ends after an open array?
  3. How would you debug a 3% failures-only-after-tool-call regression?
E Production incident → action → validation
Constraint and investigation: An exam generator emits a valid JSON object but duplicates question IDs, crashing persistence. Add deterministic uniqueness and totals checks after schema validation; reject before DB writes, then benchmark error slices and recovery latency.
Instrument, evaluate and release criteria: Track syntactic validity, schema-validity, domain-invariant pass rate, retry count, duplicate side effects and p95 end-to-end latency; require safe failure on exhausted retry budgets.
F Interview takeaways
  • JSON syntax ≠ schema ≠ domain correctness.
  • Native constrained decoding still needs application validation.
  • Side effects demand idempotency and approval boundaries.
LESSON 03 / 16
Reduce hallucinations and implement evidence-based abstention
Engineer evidence-conditioned answers and an explicit unanswerable path, not only better prose.
A Interviewer questions
  1. How do you know a retrieved passage actually supports an answer?
  2. What should an LLM do when sources disagree or contain no answer?
  3. How can you tune abstention without sacrificing all useful coverage?
B Deep technical explanation
Mechanism and data flow
A grounded QA system retrieves candidate sources using authorization-aware search, reranks passages, checks whether any evidence entails the requested claim, and either answers with traceable spans or abstains. An LLM can fabricate citations even when provided evidence, so cited spans must be checked against retrieved document text and version IDs. Separate retrieval miss, unsupported generation, false entailment and unsupported authority claims. A confidence or answerability classifier may be calibrated using labeled answerable/unanswerable cases; prompt text saying “say I do not know” is not a guarantee. For contradictory evidence, disclose disagreement and source recency rather than silently picking one.
Mathematics and invariants
Selective accuracy(τ) = correct_answered(τ)/answered(τ); coverage(τ) = answered(τ)/all_questions. Evaluate risk-coverage curves as abstention threshold τ varies. Calibration must use held-out data.
Architecture and alternatives
RAG addresses missing/updated facts; entailment or verification addresses unsupported claims; deterministic tools cover arithmetic and database truth. Fine-tuning style alone cannot guarantee factual grounding.
Implementation and instrumentation
Store citations as {document_id, version, span_start, span_end}; verify each quoted phrase substring/source access. Add answerability labels and counterfactual unanswerable prompts to golden sets.
Latency, memory, cost and scaling
Verifier and reranker calls can dominate latency; evaluate marginal gains by domain and cache where safe. Overly aggressive abstention lowers utility even when hallucination rate falls.
Failure modes and traps
High embedding similarity does not imply entailment. A linked source may contradict a claim. A model self-reported numeric confidence is not necessarily calibrated.
C Interview-ready spoken answer
“I measure two separate failures: retrieval not finding decisive evidence and generation asserting claims the evidence does not support. I require authorized source spans, verify citations, and calibrate a clear abstention path on answerable and unanswerable cases. I optimize the supported-answer error rate alongside coverage, not hallucinations alone.”
D Follow-up pressure test
  1. How do you measure an answer that is partially supported?
  2. When would you prefer a deterministic lookup to retrieval?
  3. Can increasing top-k make faithfulness worse?
E Production incident → action → validation
Constraint and investigation: A financial policy assistant invents an eligibility exception. Inspect retrieval recall and document versions, run claim-to-evidence verification, and introduce abstention when no current policy clause supports the exception.
Instrument, evaluate and release criteria: Track context recall, citation precision, supported-claim rate, false-answer rate on unanswerables, selective accuracy, coverage and p95 response time.
F Interview takeaways
  • Ground claims to versioned spans.
  • Abstention is a measurable risk-coverage trade-off.
  • Source presence is not proof of support.
LESSON 04 / 16
Handle outdated model knowledge and deprecated code generation
Choose live retrieval, version pinning, and executable validation instead of pretending model weights auto-update.
A Interviewer questions
  1. A code assistant writes deprecated SDK syntax. What fixes the root cause?
  2. How do you safely answer questions about current policy or API versions?
  3. What should you do if the latest documentation is unavailable?
B Deep technical explanation
Mechanism and data flow
Base-model knowledge is bounded by training and adaptation; prompting for “latest” does not fetch current data. Route queries requiring freshness to official documentation, known releases or authenticated APIs with citation and retrieval timestamps. Tag sources with publication time, effective date, library version, and validity window. For code, use the project’s actual dependency lockfile, resolve docs for its pinned version, compile/test generated code in a sandbox with permission-safe tools, and return diagnostics rather than untested guarantees. Handle doc conflicts by version and release channel; do not assume a later publication supersedes the active runtime.
Mathematics and invariants
Freshness age = now − source_verified_at. An effective policy version must satisfy valid_from ≤ decision_time < valid_to (if valid_to exists); recency alone is insufficient.
Architecture and alternatives
Retrieval and official tools excel at mutable facts. Fine-tuning can improve syntax/style but should not be the only source of changing release APIs or legal requirements.
Implementation and instrumentation
Provide dependency-aware search with allowlisted vendor docs, package metadata, code lint/type checks and integration tests. Record doc URI, SDK version, timestamp and test command exit status.
Latency, memory, cost and scaling
Extra retrieval and sandbox testing cost latency; asynchronous background refresh can pre-index authoritative docs, but must keep permission/version boundaries. Cache keys include requested version.
Failure modes and traps
An API endpoint existing in the latest guide may not exist in production. Web page freshness, effective date and user environment are different clocks.
C Interview-ready spoken answer
“I do not solve stale knowledge by telling a static model to be newer. I resolve versions from the actual environment, retrieve source-of-truth documentation, generate against a pinned API, and verify via compilation/tests. When trusted sources are unavailable, I say what is unverified instead of inventing an API.”
D Follow-up pressure test
  1. What if docs and package type stubs disagree?
  2. How do you handle a security advisory for a version that cannot yet be upgraded?
  3. Should a system automatically apply generated migration code?
E Production incident → action → validation
Constraint and investigation: After a framework major update, suggested code fails with missing imports. Compare pinned lockfile and current docs, create version-scoped retrieval filters, then run sandboxed tests on a representative app.
Instrument, evaluate and release criteria: Track tested-code pass rate, version-mismatch failures, citation freshness, unsupported claims, migration regressions and execution sandbox isolation.
F Interview takeaways
  • Weights do not know future releases.
  • Resolve target versions before searching.
  • Tests beat persuasive code explanations.
LESSON 05 / 16
Diagnose tokenizer inefficiencies in specialized domains
Measure token inflation, routing failures and the real costs of domain vocabulary fragmentation.
A Interviewer questions
  1. Why can a medically meaningful term be split into many subwords?
  2. How would you prove tokenizer inefficiency is causing money or accuracy issues?
  3. Would you retrain the tokenizer of a frozen base LLM?
B Deep technical explanation
Mechanism and data flow
Tokenizers map bytes or normalized strings into vocabulary IDs according to learned segmentation and merge rules. Rare domain identifiers, low-resource scripts, code symbols, and Unicode normalization can produce longer token sequences. Token inflation increases prefill length, attention/KV demand, context truncation risk, and billable tokens. But a fragmented term may still be correctly represented through multiple subwords; splitting alone does not prove low accuracy. Audit corpus token-per-character/byte distributions by language and term class; compare segmentations across candidate tokenizers and test end-task retrieval/generation metrics.
Mathematics and invariants
Inflation ratio R = tokens_domain / tokens_baseline for a matched corpus, or tokens per UTF-8 byte. Transformer full-attention prefill pair count scales ≈ N² per head, though optimized kernels reduce memory materialization.
Architecture and alternatives
Keep the pretrained tokenizer unless you can jointly adapt embeddings/model weights and safely migrate serving tools. Domain abbreviations can be handled via preprocessing, aliases, retrieval and terminology lexicons.
Implementation and instrumentation
Inspect exact Unicode input bytes and normalized output; run tokenizer.encode over realistic logs, outliers and multilingual/code fixtures. For any tokenizer change, update embedding matrices and retrain/adapt embeddings; migrate dependent indexes and templates.
Latency, memory, cost and scaling
Vocabulary expansion changes checkpoint compatibility and serving dimensions, may break prompt caching or fine-tunes. Increased token length inflates runtime, not just input billing.
Failure modes and traps
Byte-level tokenization generally avoids truly unknown bytes but may use more tokens; WordPiece systems can use [UNK]. Avoid asserting all tokenizers share one unknown-token policy.
C Interview-ready spoken answer
“I quantify tokens per byte and per domain term, then relate inflation to truncation, TTFT, KV memory and task quality. I start with safe vocabulary-aware preprocessing or model selection. I would not swap tokenizers under a frozen checkpoint because token IDs and embedding rows are coupled.”
D Follow-up pressure test
  1. What about invisible Unicode joiners or emoji sequences?
  2. Why might normalization fix one script but corrupt another?
  3. How do tokenization changes affect fine-tuned LoRA adapters?
E Production incident → action → validation
Constraint and investigation: An internal legal assistant hits its context budget early on contract IDs and non-English text. Profile tokens/byte by document language, ensure lossless ingestion, and test normalization rules on gold labels before changing model family.
Instrument, evaluate and release criteria: Measure domain token inflation, truncated-question rate, recall/accuracy by language, p95 TTFT and per-answer token costs.
F Interview takeaways
  • Measure inflation on real corpora.
  • Token fragmentation ≠ automatic comprehension failure.
  • Tokenizer/embedding weights form a coupled contract.
LESSON 06 / 16
Resolve context-window exhaustion in long-document applications
Build explicit budgeting, retrieval, progressive summarization, and invariant preservation.
A Interviewer questions
  1. How would you budget context when tools, conversation, documents and output all compete for tokens?
  2. When does retrieval outperform simply increasing the context window?
  3. How do you stop context compaction from deleting a safety-critical approval?
B Deep technical explanation
Mechanism and data flow
Count the true rendered model input: system/developer instructions, tool specs and responses, current task, selected documents, chat history, delimiters and reserve for generation. Reject or compact BEFORE overflow, not after the API throws. For long evidence, chunk and retrieve with metadata; use hierarchical map/reduce summaries with retained citations and a versioned manifest of omitted material. Maintain a separate durable state store for approved actions, constraints, access boundaries and current objective. If the task requires global document coverage, use multi-pass extraction rather than treating top-k retrieval as complete.
Mathematics and invariants
Budget constraint: T_system + T_history + T_tools + T_evidence + T_output_reserved + T_margin ≤ T_context. For ordinary full attention, arithmetic work includes O(N² d) attention terms; actual memory depends on kernels and cache.
Architecture and alternatives
Long-context stuffing minimizes infrastructure but can degrade relevance. RAG trades retrieval omissions for lower context cost; hierarchical summarization trades exactness for compression. Use hybrid designs when appropriate.
Implementation and instrumentation
Write a deterministic context assembler with priority tiers, document IDs, source spans, per-segment token counts and a hard output reserve. Test adversarial and late-position facts; never summarize secrets into a less protected store.
Latency, memory, cost and scaling
Long prompts raise TTFT and memory; repeated large histories increase cost. Chunking and summarization add preprocessing overhead and can accumulate factual drift.
Failure modes and traps
A reported context limit is not a guarantee of reliable utilization; “lost in the middle” is an empirical quality effect. Sliding windows do not magically preserve discarded evidence.
C Interview-ready spoken answer
“I make context a budgeted resource. I reserve output tokens, retain high-priority instructions and durable task state, select evidence through retrieval, and use loss-aware summarization for history. For whole-document tasks I use iterative coverage with traceable sources, then validate completeness and long-position robustness.”
D Follow-up pressure test
  1. How can you guarantee a compliance exception is not summarized away?
  2. When is full-document map/reduce safer than retrieval?
  3. What happens when a tool returns 200k unexpected tokens?
E Production incident → action → validation
Constraint and investigation: A contract QA system silently drops older conversation constraints after ten turns. Inspect the assembled prompt, compaction trace and unreferenced state; restore durable constraints and add prompt-budget admission.
Instrument, evaluate and release criteria: Zero hard-overflow failures at supported limits, preservation of critical constraints, evidence recall, answer completeness by source location, TTFT and token cost.
F Interview takeaways
  • Count every message and tool payload.
  • Persist invariants outside lossy summaries.
  • Test long-context position sensitivity.
LESSON 07 / 16
Optimize KV cache memory under high concurrency
Translate architecture into per-token bytes and use token-aware admission.
A Interviewer questions
  1. Estimate KV memory for a 32-layer, 8-KV-head, 128-dim, BF16 model at 32k tokens.
  2. Why can page allocation help fragmentation but not eliminate KV growth?
  3. What risks arise when evicting a KV span while the model is still decoding?
B Deep technical explanation
Mechanism and data flow
At every layer, each retained token stores one K vector and one V vector per KV head; memory scales with active sequences, layers, KV heads, head dimension and element bytes. GQA reduces KV heads relative to MHA while preserving query heads, lowering stored bytes, though weights/attention compute have other costs. With paged KV, a logical token sequence maps to physical fixed-size blocks; free blocks are recycled on completion. Prefix reuse can share immutable KV blocks only with exact matching model, position and authorization constraints. Eviction/quantization/offload can save VRAM but introduces accuracy, bandwidth and implementation trade-offs.
Mathematics and invariants
KV bytes = 2 × L × H_kv × d_head × N_live_tokens × b. Example: 2×32×8×128×32768×2 = 4,294,967,296 bytes = 4 GiB for one 32k-token sequence (no metadata/headroom).
Architecture and alternatives
Options: limit maximum active tokens, reduce batch size, use a GQA/MQA-compatible model, supported KV quantization, paging, prefix sharing or CPU offload. Rank by quality impact and measured bottleneck.
Implementation and instrumentation
Track resident and allocated KV blocks, fragmentation, per-request live token count, prefix reuse, swap/page faults and OOM. Account for active generation growth, allocator overhead, weights, CUDA graph buffers and activation workspaces.
Latency, memory, cost and scaling
Per-sequence 4 GiB × concurrency grows fast; 20 conversations at max context would need 80 GiB KV alone in this example. Aggressive offload adds HBM/PCIe copy stalls.
Failure modes and traps
Do not confuse KV cache with logits cache or per-step compute elimination; one-token queries still attend to historical keys. PagedAttention is primarily a memory management mechanism, not an asymptotic attention complexity reduction.
C Interview-ready spoken answer
“I budget KV as two tensors per layer/token/KV head. I multiply bytes per token by the SUM of live context lengths, add reserves, then gate admission and track fragmentation. Paging fixes allocator waste, GQA cuts cache width, and quantization or offload trades quality or bandwidth for capacity.”
D Follow-up pressure test
  1. How do prefix shares handle two tenants with identical prompts?
  2. What is the effect of 8 KV heads vs 32 at fixed head dimension?
  3. Why do pending output budgets matter before generation begins?
E Production incident → action → validation
Constraint and investigation: A GQA serving cluster OOMs only during many long conversations. Analyze token-length distribution and physical block high-water, enforce token-aware scheduling and reserve worst-case growth or graceful preemption.
Instrument, evaluate and release criteria: Validate zero OOM at defined peak mix, p99 TPOT, cache block waste, quality parity after KV quantization and bounded admission rejection.
F Interview takeaways
  • KV grows linearly with total resident tokens.
  • GQA changes stored head count; paging changes allocation.
  • Budget decode growth, not only prompt length.
LESSON 08 / 16
Handle OOM from long-context attention
Distinguish quadratic attention-score materialization from weight/KV/activation OOM.
A Interviewer questions
  1. Why can a naive attention kernel OOM at long sequence lengths even when weights fit?
  2. How does FlashAttention change HBM traffic without making exact full attention O(N)?
  3. When is sliding-window attention a functional change rather than a free optimization?
B Deep technical explanation
Mechanism and data flow
Naively computing QKᵀ for N tokens makes an N×N matrix per head, and softmax/probability intermediates can require O(HN²) HBM bytes. IO-aware tiled kernels compute exact attention with online softmax statistics while avoiding persistent full score matrices. Complexity of exact full attention arithmetic remains O(N² d), even if memory footprint falls. Training additionally stores/derives activations and gradients; activation checkpointing trades recompute for memory. In decode, a KV cache requires O(N) storage per stream, and attention scans keys linearly per generated step. Sliding-window/local attention reduces interactions by limiting visibility and may lose long-range facts.
Mathematics and invariants
Naive fp16 score buffer alone ≈ B×H×N²×2 bytes; with B=1,H=32,N=32768 this is 64 GiB (single materialized score tensor). Exact full-attention FLOPs still scale approximately with N².
Architecture and alternatives
Use optimized exact kernels first if quality requires global attention; try sparse/sliding patterns only with a model supporting the mask and evaluated long-range tasks. Reduce prompt length, microbatch and parallelism when appropriate.
Implementation and instrumentation
Profile peak allocated/reserved VRAM by kernel and stage, prefill vs decode, activation checkpointing, unsupported attention fallback, masking shape and backend. Stress high-head/high-length cases.
Latency, memory, cost and scaling
FlashAttention may shift the OOM source to KV, weights or workspaces. Larger context can overwhelm latency even when memory fits. Alternative masks change inductive bias and usually require matching training.
Failure modes and traps
Do not claim FlashAttention reduces asymptotic exact attention FLOPs to O(N); it reduces memory traffic and peak intermediate storage. A GPU OOM stack trace may point downstream from the earlier allocation.
C Interview-ready spoken answer
“First I separate full-sequence attention intermediates from KV and other allocations. I switch to verified tiled exact kernels when the N² score materialization is the problem, then profile new bottlenecks. LESSON 14 / 16
Understand ViT, multimodal Transformers and vision-language models
Trace image-to-token data flow and distinguish visual encoders, projectors and autoregressive text heads.
A Interviewer questions
  1. How does ViT turn a 224×224 image into tokens?
  2. How does a vision-language model fuse image and text features?
  3. Why can a multimodal assistant fail on tables even with accurate OCR text?
B Deep technical explanation
Mechanism and data flow
A ViT partitions an image into fixed-size patches, flattens each patch and linearly projects it into a model embedding dimension. For H=W=224 and P=16, there are (224/16)²=196 patches, often plus a classification token in classifiers. Each image patch is a learned feature vector; positional information is required to reconstruct layout. Modern VLM pipelines may use a vision encoder followed by a trainable connector/projector that maps vision features into a language model token space, or use cross-attention / unified multimodal Transformer blocks. High-resolution images often use tiling/crops and multiple token groups. Image tokens and text tokens compete for context and compute. Pixel/object recognition, spatial grounding, chart reasoning and OCR are different subproblems.
Mathematics and invariants
Number of square patches N_p=(H/P)(W/P), assuming divisibility. With 224×224×3 and P=16, each patch has 16×16×3=768 raw channel values projected to d_model. Self-attention pair work over patch tokens scales O(N_p²).
Architecture and alternatives
Contrast encoder-projector-decoder VLMs, cross-attention fusion, and unified tokenizers. Choose based on needed localization, latency, training access and modality alignment.
Implementation and instrumentation
Instrument image preprocessing, resizing/crops, encoder latency, number of vision tokens, text-token budget, grounding tests and OCR/table evaluation. Keep document coordinates for citation and table extraction.
Latency, memory, cost and scaling
Smaller patches and image tiling grow token counts rapidly; sending ten pages can overwhelm a context budget. Visual preprocessing can irreversibly lose small text or table lines.
Failure modes and traps
A ViT patch embedding is not an image caption. Not every VLM uses the same cross-attention strategy. High benchmark VQA accuracy may hide severe chart/math or multi-page errors.
C Interview-ready spoken answer
“A ViT converts images into a sequence of projected patches with positional information. VLMs connect those visual features to text decoding through projection, cross-attention or joint token processing. I budget visual tokens, preserve layout metadata, and evaluate OCR, spatial reasoning, chart interpretation and grounded citations separately.”
D Follow-up pressure test
  1. What changes when patch size halves?
  2. Why might high-resolution downscaling erase a spreadsheet footnote?
  3. How do you detect text-only shortcut learning in multimodal QA?
E Production incident → action → validation
Constraint and investigation: A multi-page invoice reader misses tax values in narrow columns. Log resize/tiling, OCR boxes, extracted cell coordinates, and compare a page-aware pipeline before expanding model size.
Instrument, evaluate and release criteria: Track field-level F1/exact accuracy, numeric consistency, layout grounding, visual token counts, p95 latency, source-box citation validity and privacy filters for images.
F Interview takeaways
  • ViT patches are tokens, not words.
  • Vision/text fusion varies by architecture.
  • Evaluate layout and OCR separately from language quality.

module8_reliability_reference.py · Python 3.10+
"""Module 8: production LLM reliability reference exercises.

Python 3.10+ standard-library-only. These are teaching tools, not a full
production policy engine, data loss prevention service, or model evaluation.
Run: python module8_reliability_reference.py
"""
from __future__ import annotations
from dataclasses import dataclass
from math import sqrt
from collections import Counter
import json
import re
import statistics
import unittest


@dataclass(frozen=True)
class Answer:
    status: str
    answer: str | None
    evidence_ids: tuple[str, ...]


def parse_grounded_answer(raw: str, allowed_ids: set[str]) -> Answer:
    """Syntax + closed schema + domain invariants + evidence authorization."""
    obj = json.loads(raw)
    if not isinstance(obj, dict) or set(obj) != {"status", "answer", "evidence_ids"}:
        raise ValueError("Unexpected or missing fields")
    if obj["status"] not in ("ok", "abstain"):
        raise ValueError("Invalid status")
    if not isinstance(obj["evidence_ids"], list) or any(
        type(x) is not str or x not in allowed_ids for x in obj["evidence_ids"]
    ):
        raise ValueError("Invalid or unauthorized evidence")
    ans = obj["answer"]
    if obj["status"] == "abstain":
        if ans is not None or obj["evidence_ids"]:
            raise ValueError("Abstention must not assert answer/evidence")
    elif not isinstance(ans, str) or not ans.strip() or not obj["evidence_ids"]:
        raise ValueError("Supported answer requires nonempty text/evidence")
    if len(set(obj["evidence_ids"])) != len(obj["evidence_ids"]):
        raise ValueError("Duplicate evidence IDs")
    return Answer(obj["status"], ans, tuple(obj["evidence_ids"]))


def risk_coverage(scores: list[float], correct: list[bool], threshold: float) -> tuple[float, float]:
    """Assumes higher evidence scores predict supported answers.

    Accuracy is undefined (NaN) if no answers are accepted.
    """
    if len(scores) != len(correct) or not scores:
        raise ValueError("Need equally sized nonempty arrays")
    keep = [i for i, s in enumerate(scores) if s >= threshold]
    return (sum(correct[i] for i in keep) / len(keep) if keep else float('nan'),
            len(keep) / len(scores))


def context_budget(segments: list[tuple[str, int]], limit: int, output_reserve: int,
                   safety_margin: int) -> tuple[list[str], list[str]]:
    """Stable-priority packing. Calls MUST retain critical segments elsewhere.

    Segments arrive in descending priority order and may be omitted whole.
    Real implementations need authoritative tokenization and invariant persistence.
    """
    available = limit - output_reserve - safety_margin
    if available < 0:
        raise ValueError("Insufficient context window")
    included, omitted = [], []
    for name, tokens in segments:
        if tokens < 0:
            raise ValueError("Token estimates must be nonnegative")
        if tokens <= available:
            included.append(name)
            available -= tokens
        else:
            omitted.append(name)
    return included, omitted


def kv_bytes(layers: int, kv_heads: int, head_dim: int, live_tokens: int,
             bytes_per_element: int = 2) -> int:
    if min(layers, kv_heads, head_dim, live_tokens, bytes_per_element) < 0:
        raise ValueError("Nonnegative dimensions required")
    return 2 * layers * kv_heads * head_dim * live_tokens * bytes_per_element


def naive_score_bytes(batch: int, query_heads: int, seq_len: int, element_bytes: int = 2) -> int:
    return batch * query_heads * seq_len * seq_len * element_bytes


def wilson_interval(successes: int, trials: int, z: float = 1.96) -> tuple[float, float]:
    """Approximate Wilson score interval, often preferred to normal CI near p≈0/1."""
    if trials <= 0 or not 0 <= successes <= trials:
        raise ValueError("Invalid counts")
    p = successes / trials
    denom = 1 + z * z / trials
    center = (p + z * z / (2 * trials)) / denom
    half = z * sqrt(p * (1 - p) / trials + z * z / (4 * trials * trials)) / denom
    return max(0., center - half), min(1., center + half)


def paired_regression(old: list[bool], new: list[bool]) -> dict[str, int | float]:
    if len(old) != len(new) or not old:
        raise ValueError("Paired nonempty outcomes required")
    improvements = sum(not a and b for a, b in zip(old, new))
    regressions = sum(a and not b for a, b in zip(old, new))
    return {"old_success": sum(old), "new_success": sum(new),
            "improvements": improvements, "regressions": regressions,
            "delta_accuracy": (sum(new) - sum(old)) / len(old)}


def span_stats(traces: list[dict[str, float]]) -> dict[str, float]:
    """Illustrative p95 via nearest-rank quantile on complete requests."""
    if not traces:
        raise ValueError("Traces required")
    keys = ("queue_ms", "retrieval_ms", "prefill_ms", "decode_ms", "postprocess_ms")
    for trace in traces:
        if any(k not in trace or trace[k] < 0 for k in keys):
            raise ValueError("Invalid tracing span")
    latency = sorted(sum(t[k] for k in keys) for t in traces)
    p95 = latency[max(0, (95 * len(latency) + 99) // 100 - 1)]
    return {"mean_ms": statistics.fmean(latency), "p95_ms": p95,
            "mean_queue_ms": statistics.fmean(t["queue_ms"] for t in traces),
            "mean_decode_ms": statistics.fmean(t["decode_ms"] for t in traces)}


def redact_demo(text: str) -> str:
    """Toy deterministic masking; NOT a sufficient production privacy control."""
    text = re.sub(r'(?i)\b(api[_-]?key\s*[=:]\s*)[A-Za-z0-9._-]{6,}', r'\1[REDACTED]', text)
    return re.sub(r'\b[\w.+-]+@[\w.-]+\.[A-Za-z]{2,}\b', '[EMAIL]', text)


def vit_patches(h: int, w: int, patch: int) -> int:
    if h <= 0 or w <= 0 or patch <= 0 or h % patch or w % patch:
        raise ValueError("Image dimensions must be positive multiples of patch size")
    return (h // patch) * (w // patch)


def watermark_z(green: int, total: int, expected_fraction: float = 0.5) -> float:
    """Illustrative independent-binomial green-list score, NOT SynthID scoring."""
    if total <= 0 or not 0 <= green <= total or not 0 < expected_fraction < 1:
        raise ValueError("Invalid green-list counts")
    return (green - total * expected_fraction) / sqrt(total * expected_fraction * (1 - expected_fraction))


def promotion_gate(candidate: dict, baseline: dict, *, max_regression: float = 0.,
                   max_cost_ratio: float = 1.5) -> tuple[bool, list[str]]:
    """Toy gate: human approval is intentionally mandatory and not inferred."""
    reasons = []
    if not candidate.get("approved_by_human", False):
        reasons.append("Human approval missing")
    if candidate["heldout_success"] < baseline["heldout_success"] - max_regression:
        reasons.append("Held-out score regressed")
    if candidate["cost_per_task"] > baseline["cost_per_task"] * max_cost_ratio:
        reasons.append("Compute cost exceeds budget")
    if candidate.get("security_violations", 0) > 0:
        reasons.append("Security violation")
    return not reasons, reasons
