LESSON 01 / 12
Transformer architecture: components and purpose
Trace parallel sequence processing through token representations, attention, MLPs, residual paths, and the language-model head.
A Interviewer questions
  1. Why did attention-based Transformers replace recurrence as the default architecture for large-scale language modeling?
  2. What does the attention layer compute that an FFN cannot?
  3. Which parts are tokenwise and which mix information across positions?
  4. What does decoder-only mean, and does it forbid cross-attention?
B Deep technical explanation
Start with the computation graph, not the buzzword. A Transformer is a deep stack of content-dependent token-mixing operations and per-position nonlinear feature transformations. A decoder-only causal LM processes token IDs T∈ℕ[B,N] and produces logits Z∈ℝ[B,N,V]. Embedding lookup maps IDs into the residual stream X∈ℝ[B,N,D]; position information is supplied by a model-dependent mechanism (learned absolute, RoPE, relative bias, etc.). Each block updates the residual stream with attention and an FFN/MLP. A final normalization and projection form next-token scores.


X⁽ˡ⁺¹⁾ = U + FFN(Norm₂(U)),   U = X⁽ˡ⁾ + Attention(Norm₁(X⁽ˡ⁾)) (representative pre-norm block)


  1. Embedding: map a token ID to a learned D-vector. Numeric IDs do not carry scalar meaning.
  2. Attention: each query position computes scores against allowed key positions, normalizes scores, and combines their values. It is the principal cross-token communication channel in a standard decoder block.
  3. MLP: independent, parameter-shared nonlinear transformation at each token location. Standard FFNs do not directly exchange information between tokens.
  4. Residual path: carry an additive identity route through depth, helping information flow and gradients.
  5. Normalization: control feature scale; exact arrangement (pre/post) and norm algorithm vary.
  6. Output head: map final hidden vectors to V vocabulary logits. Weights may be tied to the input embedding table.


Why scale? Across positions, attention matrix multiplication can be parallelized during prefill—unlike a sequential hidden-state recurrence. This does not make full attention free: score interaction count grows quadratically with sequence length, and autoregressive generation still requires a dependency on preceding tokens. Hardware-efficient matrix operations and specialized attention kernels are crucial.


Architecture boundary: the original 2017 Transformer is an encoder–decoder model. A GPT-style decoder-only model uses causal self-attention without the original encoder–decoder cross-attention sublayer; multimodal/hybrid decoders may add cross-attention. Encoder layers commonly use bidirectional attention; do not conflate attention visibility and model family.


Engineering benefits
Parallel sequence computation, flexible contextual mixing, scale-friendly accelerator kernels, reusable pretrained representations.
Costs & failures
Quadratic full-attention work, expensive prefill at large N, long-sequence sensitivity, numerical mask bugs, throughput-vs-latency contention.
C Interview-ready spoken answer
A decoder-only Transformer maps token IDs into a residual stream, repeatedly mixes accessible token information using causally masked attention, applies a per-token nonlinear MLP, and projects final hidden states to vocabulary logits. Attention is the cross-token operator; the MLP transforms local features. Residuals and normalization make deep optimization viable. Its parallel prefill is a key advantage over recurrence, although full attention is quadratic in sequence length and generation remains autoregressive.
D Follow-up pressure test
  1. Does the FFN communicate information between tokens? Strong response: no, independent per-position computation; previous attention can inject context.
  2. Can the model generate all output tokens at once? Strong response: teacher-forced training parallelizes sequence positions; autoregressive sampling is sequential unless using other decoding methods.
  3. Why is the word decoder misleading here? Strong response: causal autoregressive architecture, not necessarily the original seq2seq decoder.
Answer by explaining the mechanism, the trade-off, and how you would test the claim.
E Production scenario
Incident: A team assumes that moving to decoder-only architecture automatically removes long-context latency.
Requirement: interactive responses while handling 32k-token prompts. Hypotheses: prefill attention, projection/MLP compute, or queueing dominates. Instrument: prefill time, TTFT, output-token rate, GPU utilization, input-length histogram, kernel timings, and queue delay. Actions: profile at representative lengths, evaluate prompt reduction/semantic retrieval, fused attention, batching policies, or alternative context strategies. Acceptance: p95 TTFT and quality meet documented targets on matched prompt-length slices; avoid claiming benchmark gains without measurement.
F Interview takeaways
  • Attention mixes context; MLP transforms each position.
  • Decoder-only implies causal modeling, not a universal layer implementation.
  • Prefill parallelism and quadratic attention coexist; decoding has sequential dependencies.


LESSON 02 / 12
One complete decoder-only forward pass
Follow concrete tensor dimensions from token IDs to vocabulary logits and one next-token cross-entropy loss.
A Interviewer questions
  1. For B=2, N=8, D=512, H=8, V=32k: list every principal tensor shape in one block.
  2. Where exactly is the causal mask applied?
  3. Why does the final token logit suffice for one-token inference but not for training?
  4. Which tensor can be reused in incremental decoding?
B Deep technical explanation
Representative shape trace: let batch B=2, sequence length N=8, hidden size D=512, heads H=8, head size dₕ=D/H=64, FFN hidden size F=2048, and vocabulary V=32,000. Keep dimensions labeled; most interview mistakes are axis errors.


StageTensor shapeWhat it represents


Input IDs[2,8]Vocabulary indices
Embedding + position[2,8,512]Residual stream
Norm / QKV linear[2,8,512] / [2,8,1536]Normalized inputs, three projections
Split Q, K, V3 × [2,8,8,64]Batch, tokens, heads, features
Transpose to attention order3 × [2,8,8,64]Batch, heads, tokens, features (same numbers here, different semantics)
QKᵀ / √dₕ[2,8,8,8]One N×N score matrix per head
Mask / softmax / weighted V[2,8,8,64]Per-head contextual outputs
Concat / out projection[2,8,512]Return to residual width
Residual + FFN[2,8,512] → [2,8,2048] → [2,8,512]Tokenwise expansion and contraction
Final norm / LM head[2,8,32000]Next-token logits for each position


  1. Lookup token and positional representations; shape [B,N,D]. In RoPE models, position may enter later at Q/K.
  2. Apply pre-attention norm, project Q/K/V, reshape into H heads, and ensure attention axes are [B,H,N,dₕ].
  3. Compute scores = Q @ K.transpose(-2,-1) / sqrt(dₕ) to obtain [B,H,N,N].
  4. Set disallowed future-key logits to negative infinity before softmax; optionally combine compatible padding masks and numeric biases.
  5. Perform stable rowwise softmax and multiply weights by V. Concatenate heads, linearly project, and add the residual.
  6. Normalize residual stream, apply MLP (e.g. SwiGLU), add second residual. Repeat across L layers.
  7. Apply final normalization and LM head [D,V]. During teacher forcing, compute loss using logits at positions 0...N-2 against target IDs at 1...N-1; ensure shifted labels are correct.


𝓛 = −(1/(B(N−1))) ∑ᵦ∑ₜ log softmax(Z[b,t,:])[token[b,t+1]]


Decode contrast: at inference, prefill computes features for the prompt and saves per-layer K/V. A new token produces a single query per head, attends against cached keys/values, appends its new K/V, and emits a final-step logit vector. This avoids recomputing old K/V projections if the cache is correct; context position IDs must stay aligned. Full forward without a cache is still valid but repeats work.
C Interview-ready spoken answer
Given B, N, D, and H, I track IDs [B,N] to embeddings [B,N,D], then Q/K/V [B,H,N,D/H], score matrices [B,H,N,N], and attention outputs back to [B,N,D]. A pre-norm residual block adds an attention update and an MLP update. After all layers, the LM head produces [B,N,V] logits. For next-token training I shift targets by one position; for generation I only sample from the final position and reuse cached K/V.
D Follow-up pressure test
  1. The shapes [2,8,8,64] look equal before/after transpose—how do you catch swapped dimensions? Strong response: annotate names, asymmetric test sizes, assertions.
  2. What if shift alignment is wrong? Strong response: wrong objective, suspicious teacher-forced loss and generation, explicit fixture.
  3. Do padding and causal masks have identical meaning? Strong response: no; one hides future keys, other ignores padded positions.
Answer by explaining the mechanism, the trade-off, and how you would test the claim.
E Production scenario
Incident: A refactor runs without exceptions but model loss increases. Inspect: compare layerwise norm outputs, QKV split order, tensor axis names, mask values, target shift, output logits against a minimal reference at short N. Instrumentation: shape assertions, per-layer activation norms, gradient finite checks, deterministic small-batch fixtures, and prefix-invariance tests. Fix: restore Q/K/V ordering or loss shift, add regression tests on asymmetric shapes such as B=2,N=7,H=4,dₕ=32. Acceptance: shape checks, finite grads, reference-output parity within floating-point tolerance, and matched validation loss behavior.
F Interview takeaways
  • Draw tensor axes, not just tensor sizes.
  • Mask scores before softmax; shift labels correctly.
  • Prefill computes a whole sequence; incremental decoding reuses keys and values.


LESSON 03 / 12
Query, Key, and Value: projections, algebra, shapes
Explain the three learned linear projections, head slicing, scores, and weighted aggregation without relying on analogies.
A Interviewer questions
  1. Can Q, K, V have different dimensions and is each derived from different input tokens?
  2. Derive WQ/WK/WV shapes for D=768 and H=12.
  3. Why do we need three projections rather than one shared embedding?
  4. Show exactly which axis QKᵀ contracts and which axis softmax normalizes.
B Deep technical explanation
Core derivation. For one residual stream X∈ℝ[B,N,D], define Q=XW_Q, K=XW_K, V=XW_V. In canonical MHA the flattened projections each have width D, and three matrices are each [D,D]; they are often computed by one fused weight W_QKV∈ℝ[D,3D]. Reshape into heads of dimension dₕ=D/H. Queries and keys live in a learned compatibility space while values carry the vectors to be mixed. Q, K, and V are computed from the same token sequence in self-attention but have different learned parameters.


qᵢ = W_Qᵀ xᵢ,  kⱼ = W_Kᵀ xⱼ,  vⱼ = W_Vᵀ xⱼ;
aᵢⱼ = softmaxⱼ( qᵢᵀkⱼ / √dₖ + mᵢⱼ );   oᵢ = Σⱼ aᵢⱼ vⱼ


Dimension example: with D=768 and H=12, dₕ=64. W_Q,W_K,W_V are each [768,768] in one common parameterization. XW_Q is [B,N,768], reshaped to [B,12,N,64]. Q @ K.transpose(-2,-1) gives [B,12,N,N]. A @ V returns [B,12,N,64]. After concatenation and output projection W_O∈ℝ[D,D], the result returns to [B,N,D].


Why separate roles? A token can be good at matching a preceding token without sending the same representation to the output. Separate Q/K/V let the model learn asymmetric search and transported content. In other variants, K/V head counts can be reduced (GQA/MQA), dₖ and dᵥ may differ, projections may include bias, and RoPE may rotate only a fraction of Q/K features. Do not assume every LLM uses a pure [D,D] projection per role.


Data flow vs. semantics: the weights are data-dependent per input because dot-products involve token features, but the linear projection weights are fixed after training. Attention probabilities are neither causal explanations nor automatically interpretable features; they are operational weights for mixing values.


Self-attention projections + output: approximately 4D² weight parameters per layer, assuming H·dₕ = D and no biases.


Debugging: assert head divisibility; ensure last axes in matmul are [-2,-1]; compare fused and unfused projections; check contiguous/transpose reshape; verify QK orientation and scale. Common bug: taking softmax over query dimension instead of keys.
C Interview-ready spoken answer
Q, K, and V are learned, separate projections of the hidden states. Each query scores permitted keys, the scale and mask are applied, softmax normalizes across key positions, and the resulting weights form a weighted sum of value vectors. With D=768 and 12 heads, each head is 64-dimensional in standard MHA, producing per-head N×N compatibility matrices. Separate projections let matching and transported information have different learned representations.
D Follow-up pressure test
  1. Do attention weights necessarily sum to 1? Strong response: each valid query row does after softmax, subject to dropout or implementation details.
  2. What is the cost of computing projections? Strong response: O(BND²) with dense [D,D] maps; compare with O(BN²D) token mixing.
  3. Can Q and K come from different sequences? Strong response: yes, that is a typical cross-attention arrangement.
Answer by explaining the mechanism, the trade-off, and how you would test the claim.
E Production scenario
Incident: Attention attends to seemingly unrelated tokens after optimization to a fused QKV kernel. Hypotheses: split-order mismatch, wrong head reshape, transpose omission, accidental Q/K sharing, or mask broadcast. Test: small deterministic model, identical projection weights, compare Q/K/V tensors and attention matrix elementwise. Instrument: score magnitude quantiles, row sum, mask leakage count, output agreement per layer. Fix: correct shape layout and add unit tests with distinct B,N,H. Acceptance: numerical parity within dtype-specific tolerance and unchanged held-out task quality.
F Interview takeaways
  • Q/K decide compatibility; V transports content.
  • Projection width, head count, and head dimension determine shapes.
  • Softmax normalizes keys for each query, never the wrong axis.


LESSON 04 / 12
Scaled dot-product attention and √dₖ
Derive the variance argument for attention scaling, investigate softmax saturation, and distinguish scaling from masking.
A Interviewer questions
  1. Why is the denominator √dₖ rather than dₖ?
  2. What assumptions justify the variance argument and when do they fail?
  3. Does scaling by √dₖ guarantee stable attention at all network depths?
  4. If dₖ=64, how should raw dot products and softmax probabilities change?
B Deep technical explanation
Attention scores: for a query q∈ℝ[dₖ] and key k∈ℝ[dₖ], define unscaled s=q·k=Σᵢ qᵢkᵢ. Under the simplifying assumptions that components are independent, zero-mean and unit-variance, E[s]=0 and Var(s)=dₖ. Standard deviation therefore grows as √dₖ. Dividing by √dₖ makes the score variance approximately one in this idealized case.


Var(Σᵢ qᵢkᵢ) = Σᵢ Var(qᵢkᵢ) = dₖ;  score = (q·k)/√dₖ


Why it matters to gradients. When logits become large relative to one another, softmax becomes near one-hot. Off-winning entries receive tiny derivatives, and the system may have a harder optimization problem. Scaling reduces dependence of typical logit magnitude on head width at initialization. It is not a proof of correct calibration; learned Q/K statistics, normalization, temperatures, and biases matter in trained systems.


Worked example: for dₖ=64, divide raw QK scores by 8. A raw score row [8,4,0] becomes [1,.5,0], which produces a noticeably more distributed softmax. Applying a mask is separate: if key j is in the future, its score should be prohibited (−∞), so its normalized weight is exactly zero in the ideal math.


Numerics: use a stable softmax (subtract maximum of finite logits) and account for fused kernels or mixed-precision accumulation. A row with all keys masked is an edge case—some implementations return NaN or require special safe handling. In causal self-attention with correctly shaped nonempty sequences, the diagonal generally provides at least one valid key, but combined padding masks can create fully masked rows.


Cost: QKᵀ is roughly 2BN²D FLOPs using multiply+add=2 and summed head width D. The scale is cheap relative to matrix products; key factors for performance include sequence length, memory traffic, and kernel fusion.


Invalid intuition
“Scaling makes Q and K unit vectors.” No: it scales scores rather than normalizing vector length.
Alternative
Cosine attention or learned temperature can change score calibration, but changes model behavior and must be evaluated rather than casually substituted.
C Interview-ready spoken answer
If Q and K dimensions are roughly independent with zero mean and unit variance, their dot-product has variance dₖ. Dividing by √dₖ keeps typical logit scale approximately invariant to head dimension. That reduces initial softmax saturation and improves gradient behavior. It is a statistical motivation, not a guarantee; masks, initialization, normalization, and mixed-precision stability still matter.
D Follow-up pressure test
  1. Is √dₖ chosen because the dot product is an average? Strong response: no, because variance rather than mean magnitude grows with dₖ.
  2. How do you detect softmax saturation? Strong response: inspect attention entropy, logit gaps, masked rows, and training gradients.
  3. What happens if the mask value is −1e4 in fp16? Strong response: semantics depend on dtype/kernel and whether fully masked rows exist.
Answer by explaining the mechanism, the trade-off, and how you would test the claim.
E Production scenario
Incident: After changing head size, training becomes unstable and attention nearly collapses to individual positions. Investigate: verify whether QK scaling was removed in a custom kernel; inspect Q/K RMS, score quantiles, attention entropy, grad norms, and logit finite checks. Experiment: compare correctly scaled reference attention with the custom kernel using fixed inputs; run short controlled training, holding optimizer and data constant. Acceptance: score and output parity, stable gradients, and restoration of validated loss trajectory without regression.
F Interview takeaways
  • Var(q·k)≈dₖ under independent unit-variance components.
  • √dₖ controls score scale, not vector norms.
  • Stable softmax and correctly combined masks remain necessary.


LESSON 05 / 12
Self-attention vs cross-attention
Identify which sequence supplies queries, which supplies keys and values, and why mask geometry changes.
A Interviewer questions
  1. Draw Q/K/V data flows for self-attention and cross-attention.
  2. If decoder tokens have length N and encoder tokens length M, what is the score shape?
  3. Why does standard decoder-only language modeling not require cross-attention?
  4. What do cached K/V represent in encoder–decoder cross-attention?
B Deep technical explanation
Self-attention: the query, key and value vectors are projected from the same sequence representation. With X∈ℝ[B,N,D], one head computes Q=XW_Q, K=XW_K, V=XW_V, so the score map has shape [B,H,N,N]. For a decoder LM, the upper triangle is masked: each position may see itself and its predecessors. Bidirectional encoder self-attention typically admits all nonpadding positions.


Cross-attention: queries come from the decoder-side representation X_dec∈ℝ[B,N,D_dec]; keys and values come from an external memory X_mem∈ℝ[B,M,D_mem] (often encoder outputs). Projection matrices can be rectangular to create compatible head widths. The score shape is [B,H,N,M]. Each decoder position can query all permitted memory slots, unless application constraints impose an additional mask.


Self: softmax(QₓKₓᵀ/√d) Vₓ   |   Cross: softmax(Q_dec K_memᵀ/√d) V_mem


Architectural uses: original Transformer sequence-to-sequence decoder has causal self-attention and cross-attention over encoder states. Decoder-only LMs instead encode prompt context in their causal self-attention stream. Vision-language or speech systems may add cross-attention to externally encoded features; simply sending multimodal tokens in a combined sequence is another design. Model labels alone do not guarantee a specific cross-attention layer.


Latency trade-offs: self-attention prefill mixing costs roughly O(BN²D). Cross-attention over memory M costs O(BNMD), plus external encoder work and memory/KV management. Static cross-attention K/V can often be computed once and reused during generation; dynamic memory invalidates reuse. Access-control masking over retrieved snippets must be enforced before the model can attend to restricted material, not merely hidden by later softmax tricks.


Mask nuance: for cross-attention, a triangular causal mask over the N×M matrix generally makes no sense unless memory elements are temporally aligned. Common masks prevent attending to padding or prohibited memory entries. Always check what “True” means for the particular attention API: PyTorch's SDPA uses True for allowed entries, while some other MHA masks use the opposite convention.
C Interview-ready spoken answer
Self-attention uses Q, K, and V projected from the same sequence, so an N-token input gives an N×N score map per head; a decoder masks future keys. Cross-attention uses decoder queries against external encoder or memory keys and values, giving an N×M map. It enables conditional generation from a separate representation but adds memory and compute, and usually has a different masking policy.
D Follow-up pressure test
  1. Would you use a causal triangle in cross-attention? Strong response: normally not; memory positions are not decoder time positions.
  2. Could a decoder-only model use multimodal information without cross-attention? Strong response: yes, merged token streams or other adapters.
  3. How does static memory help decode throughput? Strong response: cache external K/V, not recompute per token.
Answer by explaining the mechanism, the trade-off, and how you would test the claim.
E Production scenario
Incident: A seq2seq summarizer silently ignores source paragraphs after padding a batch. Hypotheses: reversed cross-attention boolean-mask convention, memory alignment bug, cached K/V from another sample. Instrument: memory indices per request, allowed-key mask visualization, attention mass over padded positions, output parity on single vs batched requests. Fix: align mask conventions, associate cache state with correct request, and test source-length extremes. Acceptance: no attention to padding/restricted positions and equivalent outputs for batched vs isolated inputs within expected tolerance.
F Interview takeaways
  • Self: N×N; cross: N×M.
  • Cross-attention is optional in a decoder-only LM.
  • Mask semantics depend on the relationship between queries and memory.


LESSON 06 / 12
Causal masking and leakage prevention
Make future-token information unavailable at the attention-score level; validate with adversarial prefix-invariance tests.
A Interviewer questions
  1. Why is a causal mask required for parallel teacher-forced training?
  2. Show the attention logit mask for sequence length 4.
  3. Why is multiplying post-softmax attention by a 0/1 mask incorrect?
  4. Can a masking bug produce excellent training loss and terrible generation?
B Deep technical explanation
Objective and visibility. A causal language model estimates p(x₁,…,xₙ)=∏ₜ p(xₜ|x₍₁:ₜ₋₁₎). During teacher-forced training, all input positions are processed in parallel; without masking, position t could read target token xₜ₊₁ from a future location and cheat. A triangular bias enforces the conditional-information boundary inside each self-attention layer.


M[i,j] = 0 if j≤i, otherwise −∞;  A = softmax((QKᵀ)/√dₕ + M)   (softmax over keys j)


Example: sequence N=4; rows are queries, columns are keys
         k₀   k₁   k₂   k₃
q₀       ✓    ×    ×    ×
q₁       ✓    ✓    ×    ×
q₂       ✓    ✓    ✓    ×
q₃       ✓    ✓    ✓    ✓


Why before softmax? If an invalid logit is left in the normalizing denominator, even multiplying its final probability by zero wastes probability mass and changes the other weights unless you renormalize. The standard safe approach is a large negative/additive forbidden bias before the normalization; fused kernels implement this logically without materializing a full mask.


Correctness invariant: changing token IDs at positions greater than t must not change logits for positions ≤t, assuming a deterministic eval-mode model and unchanged position/padding metadata. This is a powerful unit test because it catches both direct and indirect leakage across multiple layers.


Packing/padding: a plain causal lower-triangle is insufficient when packing independent documents into one tensor; without a block-diagonal or segment-aware mask, later segments can see earlier documents. Left padding, cached decode offsets, and chunked prefill make mask alignment nontrivial. Avoid fully masked query rows where possible; implementations differ in handling them.


Complexity: in full prefill the mask changes which interactions are valid, but a naïvely materialized N×N score tensor still costs O(N²) memory; fused and sparse-aware kernels may reduce intermediate storage.
C Interview-ready spoken answer
The causal mask enforces the factorization of next-token prediction while processing all training positions in parallel. For query i, only keys j≤i are allowed; future-score entries are effectively −∞ before softmax. I verify correctness by mutating suffix tokens and asserting that earlier-position logits remain unchanged. I also test packed sequences, padding, and cache offsets because those can leak data even when a triangular mask exists.
D Follow-up pressure test

LESSON 07 / 12
Multi-Head Attention: representation and output projection
Explain head partitioning, concatenation, output mixing, head diversity limitations, and practical variants.
A Interviewer questions
  1. Why multiple attention heads instead of one larger head?
  2. What is the output shape after concatenating heads and why do we need W_O?
  3. Do heads necessarily learn unique linguistic relationships?
  4. Does increasing head count with fixed D reduce the N² work?
B Deep technical explanation
Standard setup. For hidden width D and H heads, split projected features into H vectors of dimension dₕ = D/H. Each head independently computes an attention distribution and weighted value mixture. Concatenate all H outputs into D features, then apply a learned output projection W_O∈ℝ[D,D]. This lets the next residual stream combine information from the different head subspaces.


headₕ = softmax(Qₕ Kₕᵀ / √dₕ + M) Vₕ;  MHA(X)=Concat(head₁,…,head_H) W_O


Mechanistic rationale: multiple learned projections can route different kinds of information—short-range copying, delimiter matching, code structure, or long-distance relations—through different subspaces. This is a capability, not a guarantee: heads may be redundant, specialized, or change roles across checkpoints. Claims about named “syntax heads” require mechanistic evidence and controlled ablations.


Complexity under fixed D: summing H head attentions still performs roughly 2BN²D score multiplications plus another 2BN²D weighted-value multiplications. Full QKV + output projection is about 8BND² FLOPs (multiply and add counted separately). Increasing H while keeping D fixed mainly changes dₕ and the number/shape of attention matrices; it does not proportionally multiply the leading N²D arithmetic, but unoptimized kernel launch/softmax costs, cache metadata, and memory traffic can increase.


Parameter comparison: in standard dense MHA with fixed D, W_Q,W_K,W_V,W_O total 4D² weights independent of H. However, per-head learned biases, relative features, architecture-specific projections, and GQA/MQA change this picture.


GQA/MQA boundary: module 6 covers detailed GQA, but at a high level, reducing the number of K/V heads can shrink decode KV-cache memory and bandwidth. It changes inference bottlenecks but is not mathematically identical to full MHA without retraining or conversion.


Debugging: use head-specific heatmaps and tests, not only averaged head attention. An average can conceal a faulty head. Check mask broadcasting to all heads, head-dimension scale, contiguous layouts, and output projection orientation.
C Interview-ready spoken answer
Multi-head attention performs content routing in several learned projection subspaces. Each head builds its own causal attention matrix, mixes value vectors, then we concatenate the head outputs and apply W_O to mix them back into the residual width. At fixed D, more heads do not automatically change 4D² projection weights or the leading N²D attention work. The number of heads affects head dimensions, implementation efficiency, and learned behavior, so I benchmark and ablate rather than assume more is better.
D Follow-up pressure test
  1. If I double H but halve dₕ, what happens to score work? Strong response: sum over heads still roughly N²D.
  2. How do you prove heads are complementary? Strong response: compare head behavior and ablate/control for retraining effects.
  3. What if a head uses the wrong causal mask? Strong response: assert per-head masked probabilities and prefix invariance.
Answer by explaining the mechanism, the trade-off, and how you would test the claim.
E Production scenario
Incident: A seemingly harmless head-count change reduces throughput with no accuracy benefit. Diagnose: unsupported or less efficient kernel layouts, smaller per-head GEMMs, or increased per-head overhead. F Interview takeaways
  • Head count is not equal to total hidden width.
  • W_O recombines head output features.

LESSON 08 / 12
Feed-Forward Networks: GELU, SiLU, SwiGLU
Compare the per-position MLP formulas, activation behavior, parameter costs, and gated variants.
A Interviewer questions
  1. Does the FFN mix token positions?
  2. Derive the two-layer GELU MLP and the three-projection SwiGLU variant.
  3. How do you compare hidden expansion sizes fairly across different FFN types?
  4. Where do FFNs dominate Transformer compute?
B Deep technical explanation
What FFNs do: attention aggregates information between positions; an FFN applies the same learned nonlinear function to each position separately. Given X∈ℝ[B,N,D], a conventional MLP expands to F features and projects back to D:


FFN_GELU(x)=W_down · GELU(W_up x+b_up)+b_down


In row-vector convention this is GELU(X W_up + b_up) W_down + b_down with shapes [D,F] and [F,D]. GELU roughly gates negative inputs smoothly; the exact Gaussian-CDF form is GELU(z)=z·Φ(z), with common approximate implementations. ReLU uses max(0,z) and has a discontinuous derivative at zero. SiLU/Swish is z·sigmoid(z).


SwiGLU: compute two independent branches of width F: U=XW_up and G=XW_gate. Multiply the up branch by a SiLU-transformed gate, then return to D: SwiGLU(X) = (SiLU(G) ⊙ U) W_down. The elementwise gate can learn richer conditional feature selection at extra projection cost.


Weights: GELU MLP ≈ 2DF;  SwiGLU ≈ 3DF (bias-free);   F_SwiGLU≈(2/3)F_GELU gives similar parameter count.


Example: if D=4096, a GELU MLP with F=16384 has about 2×4096×16384=134.2 million weight parameters. A comparable-parameter SwiGLU width is approximately 10923, because it has three large projection matrices. Exact hidden-width rounding matters for hardware efficiency and tensor parallel layouts.


Compute: approximately 4BNDF FLOPs for GELU projections and 6BNDF for SwiGLU projections using the same F (multiply+add=2). At short sequence lengths, dense linear layers and model-weight bandwidth can dominate serving; at long prefill N, attention's N² term may become important. MoE replaces dense FFN with routed expert computation in some architectures.


Failures: mistakenly applying an activation to the residual sum, omitting a gate multiplication, using the wrong tensor order in fused kernels, FP16 overflow with large activations, or comparing expansions at unequal parameter budgets. Debug with scalar activation plots, shape assertions, finite-value tests, and reference parity.
C Interview-ready spoken answer
The FFN is a positionwise nonlinear feature processor; it does not itself mix tokens. A standard block expands from D to F, applies GELU or another activation, and projects back to D. SwiGLU uses separate up and gate projections, multiplies SiLU(gate) by up, and projects down. It has three dense projections rather than two, so when comparing equal parameter budgets I reduce the gated hidden width by roughly a third.
D Follow-up pressure test
  1. Why can an FFN still use prior token information? Strong response: its input was contextualized by attention.
  2. Is GELU equal to ReLU for negative values? Strong response: no, smooth nonzero behavior for much of negative region.
  3. What is the compute cost when F=4D? Strong response: GELU projection FLOPs ≈16BND²; SwiGLU with same F ≈24BND².
Answer by explaining the mechanism, the trade-off, and how you would test the claim.
E Production scenario
Incident: Converting an FFN to a gated variant causes an OOM at the same hidden expansion factor. Instrument: parameter count, temporary tensor allocations, peak memory, matmul FLOPs, and per-block time. Diagnosis: extra gate projection and activations increase memory/compute. Mitigate: retune F for matched parameter budget, fuse elementwise operations, profile checkpointing or precision. Acceptance: specified memory budget and throughput while validation quality matches agreed guardrails.
F Interview takeaways
  • FFNs are tokenwise; attention creates contextual inputs.
  • SwiGLU uses up/gate/down, not just activation swap.
  • Compare equal compute or parameter budgets, not arbitrary equal F.


LESSON 09 / 12
Residual connections and gradient propagation
Reason about identity paths, Jacobians, training depth, and the effect of normalization placement.
A Interviewer questions
  1. Why does residual addition help train deep Transformer stacks?
  2. Write the local Jacobian of y=x+F(x).
  3. Do residual connections guarantee no vanishing/exploding gradients?
  4. How can residual scaling alter optimization?
B Deep technical explanation
Residual route: instead of forcing a sublayer to replace its input, compute y=x+F(x), where F can be attention or an MLP branch. The identity route allows the residual stream to carry information forward even if a residual branch is initially small or poorly conditioned.


y=x+F(x);   ∂y/∂x=I+J_F(x);   ∂𝓛/∂x=(I+J_F)ᵀ∂𝓛/∂y


Why it helps: the gradient includes a direct identity contribution rather than passing exclusively through a long product of nonlinear Jacobians. However, the total gradient is still a sum of paths and can exhibit cancellation, explosion, or instability. Saying “residuals solve vanishing gradients” without caveats is incomplete.


Stacked residuals: for x_{l+1}=x_l+F_l(x_l), telescoping gives x_L=x_0+Σ_l F_l(x_l); this offers an additive interpretation, but since every branch depends on previous states, it is not a set of independent corrections. In backprop, many identity-plus-branch paths contribute.


Pre-norm interaction: in x+F(Norm(x)), the bypass does not pass through a normalization operator. In post-norm Norm(x+F(x)), gradients are transformed by normalization after each residual sum. This is part of why many deep GPT-like models choose pre-norm, though precise stability and quality depend on initialization, scaling, and architecture.


Residual scaling and initialization: some models scale residual branches at initialization, use gating, or choose layer-dependent multipliers to control depth-dependent activation growth. This is not interchangeable with dropping residuals: it trades stability, representation update strength, and optimization dynamics.


Validation: inspect gradient norm per block and branch, activation RMS by depth, optimizer loss curve, exploding/vanishing flags, and loss sensitivity to residual scale. Use a zeroed-branch test: if F(x)=0, pre-norm residual sublayer should return x exactly within floating-point behavior.
C Interview-ready spoken answer
Residuals compute y=x+F(x), so the backward Jacobian contains an identity term I in addition to the sublayer Jacobian. This supplies a direct gradient route and helps preserve information through depth. It does not mathematically guarantee stable optimization; normalization placement, residual scales, activation growth, and initialization still matter. I would monitor layerwise activation RMS and gradient norms rather than assume residuals prevent every instability.
D Follow-up pressure test
  1. Why can residual gradients still explode? Strong response: products/sums of I+J across depth can grow and branches may dominate.
  2. What differs between pre-norm and post-norm residual paths? Strong response: norm lies inside vs after the bypass and changes the Jacobian.
  3. How would you test residual implementation? Strong response: zero residual branch, check identity and gradient path.
Answer by explaining the mechanism, the trade-off, and how you would test the claim.
E Production scenario
Incident: A newly deepened 48-layer decoder diverges after several hundred optimizer steps. Hypotheses: residual magnitude accumulation, optimizer LR, norm placement, initialization or mixed-precision overflow. Instrument: blockwise activation/gradient RMS, NaN origin, loss scale, optimizer state statistics. Experiments: one variable at a time—pre-norm, residual scaling, initialization, gradient clipping; compare training/validation over matched tokens. Acceptance: finite stable training to the target schedule and no meaningful quality regression.
F Interview takeaways
  • Residual Jacobian is I+J_F.
  • Identity path helps but never guarantees numerical stability.
  • Norm placement changes the actual residual gradient route.


LESSON 10 / 12
LayerNorm vs RMSNorm: exact computation
Compute normalization across the feature dimension and reason about mean subtraction, parameters, and numerical stability.
A Interviewer questions
  1. Write LayerNorm and RMSNorm equations for the last dimension.
  2. What is the difference between centering and scaling?
  3. When is RMSNorm a reasonable replacement and when is it not drop-in?
  4. How do epsilon placement and half-precision accumulation affect results?
B Deep technical explanation
LayerNorm normalizes each token independently across its D hidden features (not across the batch), typically with a trainable scale γ and bias β. Compute μ=(1/D)Σᵢxᵢ and σ²=(1/D)Σᵢ(xᵢ−μ)², then LN(x)ᵢ=γᵢ(xᵢ−μ)/√(σ²+ε)+βᵢ.


LN(x)ᵢ = γᵢ (xᵢ−μ)/√(σ²+ε) + βᵢ;  RMSNorm(x)ᵢ = γᵢ xᵢ/√(mean(x²)+ε)


RMSNorm divides features by their root-mean-square magnitude and usually learns only γ. It does not subtract the feature mean, so the normalized output is not generally zero-mean. This can reduce operations and is used in many modern decoder LMs, but its behavior is not mathematically equivalent to LayerNorm.


Example: x=[1,2,3], with unit γ and zero β. LayerNorm subtracts μ=2 and divides by sqrt(2/3+ε), yielding approximately [-1.2247,0,1.2247]. RMSNorm divides by sqrt(14/3+ε), yielding about [0.4629,0.9258,1.3887]. The outputs differ in both mean and direction.


Data flow: normalization preserves shape [B,N,D]. It computes statistics over only the last D dimension; accidentally normalizing over sequence or batch can create training/inference mismatch and even violate causality if future tokens influence normalization of earlier ones.


Numerical issues: use epsilon inside the square root as defined by the selected implementation, especially near zero variance. Many kernels accumulate sums/means in FP32 when input is BF16/FP16. Choice of ε, bias and weight conventions, cast locations, and normalization axis affect checkpoints and inference parity. Never swap LayerNorm for RMSNorm in an existing pretrained model without validating or adapting weights.


Performance: both are O(BND) in feature reads/elementwise operations; differences often involve memory traffic, fusion, and GPU kernel overhead. Neither eliminates quadratic attention.
C Interview-ready spoken answer
LayerNorm centers each token vector by subtracting its feature mean and divides by feature standard deviation, with learned scale and typically bias. RMSNorm only rescales by root-mean-square magnitude and generally uses a learned scale without mean subtraction. Both act across the feature dimension per token. RMSNorm can simplify computation, but swapping norms changes learned behavior, so I would test numerical parity and task quality rather than treat it as a free speedup.
D Follow-up pressure test
  1. Why do two tokens in one batch not share LN statistics? Strong response: reduction is over each token’s feature axis.
  2. What happens if RMSNorm input is all zeros? Strong response: ε avoids division by zero; output stays zero absent bias.
  3. Can we replace norm in an existing checkpoint? Strong response: incompatible statistics and affine forms; adaptation/quality validation required.
Answer by explaining the mechanism, the trade-off, and how you would test the claim.
E Production scenario
Incident: Model outputs differ after migrating a normalization kernel to mixed precision. Hypotheses: reduction in low precision, epsilon placement, different γ dtype, wrong axis. Instrument: per-token mean/variance/RMS and max absolute difference vs FP32 reference across random, constant, and near-zero vectors. Fix: standardize norms and accumulation semantics; ensure inference/training match. Acceptance: bounded tensor parity error on fixtures and no quality regression at deployed precision.
F Interview takeaways
  • LN subtracts mean; RMSNorm does not.
  • Both normalize feature dimensions per token, not batch statistics.
  • Epsilon/casting/axis errors can silently damage quality.


LESSON 11 / 12
Pre-Norm vs Post-Norm Transformer blocks
Derive update order, explain gradient-route differences, and compare stability and representational trade-offs.
A Interviewer questions
  1. Show the exact equations for pre-norm and post-norm residual blocks.
  2. Why is pre-norm common in deep causal decoders?
  3. Is post-norm always worse or unusable?
  4. Does using pre-norm eliminate the need for an output normalization?
B Deep technical explanation
Pre-norm applies normalization before the sublayer and adds its output directly to the residual stream. A representative attention+FFN block is:


u = x + Attn(Norm₁(x));   y = u + FFN(Norm₂(u))


Post-norm instead normalizes after each sublayer's residual addition:


u = Norm₁(x + Attn(x));   y = Norm₂(u + FFN(u))


Key optimization difference: pre-norm's main bypass x→x+branch is an exact identity addition at each block; post-norm routes even the skip contribution through the norm Jacobian. The latter can make deep optimization more sensitive to initialization, LR warmup, and layer depth. Most contemporary autoregressive LMs use pre-norm-like layouts or closely related variants, but post-norm designs can train successfully with proper recipe and may differ in final-layer representation behavior.


Do not confuse normalization type and placement: RMSNorm vs LayerNorm is one axis; pre-norm vs post-norm is a separate axis. A decoder can be pre-LayerNorm or pre-RMSNorm, and may apply a final norm before the LM head. The norm before the attention branch and the norm before FFN usually have separate learned parameters.


Memory and speed: both layouts have comparable leading-order FLOPs and parameter counts for matching sublayers; differences lie in kernel fusion, activation checkpointing, and training stability. The main trade-off is optimization behavior rather than a guaranteed major inference-cost reduction.


Common mistakes: applying the same norm twice to wrong state, adding residual after normalization in a supposed post-norm implementation, forgetting final norm in a pre-norm stack, silently loading weights trained under a different layout. Compare outputs with a hand-constructed block where attention/FFN return zeros to expose update-order differences.
C Interview-ready spoken answer
In pre-norm I normalize before attention or FFN, then add the sublayer output to the unnormalized residual stream. In post-norm I normalize after each residual addition. Pre-norm offers a cleaner identity gradient path and often helps training very deep causal models, but post-norm is not categorically broken. I also distinguish norm placement from LayerNorm versus RMSNorm and verify any final normalization before loading or exporting a checkpoint.
D Follow-up pressure test
  1. If F=0, what does pre-norm return vs post-norm? Strong response: pre-norm returns x; post-norm returns Norm(x).
  2. Is pre-norm always more accurate at a matched compute budget? Strong response: no universal guarantee, requires controlled experiment.
  3. Does changing pre/post norm preserve pretrained weights? Strong response: no, different forward graph and state semantics.
Answer by explaining the mechanism, the trade-off, and how you would test the claim.
E Production scenario
Incident: A checkpoint produces nonsensical completions after porting model code even though every tensor shape matches. Hypothesis: norm placement was changed during implementation. Diagnosis: trace sublayer outputs, compare zero-branch probes, checkpoint architecture metadata, and layerwise parity against source implementation. Fix: restore precise norm/residual order and load correct final-norm weights. Acceptance: matching reference logits within expected precision tolerance and matched held-out evaluation.
F Interview takeaways
  • Pre: x+F(Norm(x)); post: Norm(x+F(x)).
  • Norm type and norm placement are independent choices.
  • Correct residual/norm order is a checkpoint-compatibility requirement.


LESSON 12 / 12
Transformer compute, memory, and scaling complexity
Estimate projection, FFN, and attention FLOPs; distinguish persistent weights, ephemeral attention activations, and KV cache.
A Interviewer questions
  1. When do projection/FFN costs exceed the N² attention cost?
  2. Estimate attention score memory for B=4,H=32,N=4096 in FP16.
  3. Why can FlashAttention remove an N² memory bottleneck without making attention arithmetic linear?
  4. How do prefill and single-token decode complexity differ with a KV cache?
B Deep technical explanation
Variables: B sequences, N tokens, model width D, heads H, head size dₕ=D/H, FFN width F, and blocks L. The following approximations treat a multiplication plus addition as 2 FLOPs, count weights without biases, and describe a standard dense full-attention layer. Hardware kernel FLOP conventions and actual activation memory vary.


Operation (per block)Approx FLOPs / paramsReason
Q,K,V,output projections8BND² FLOPs; 4D² weights4 dense D×D maps
QKᵀ and AV4BN²D FLOPsTwo sequence-mixing matrix products
GELU FFN4BNDF FLOPs; 2DF weightsTwo dense projections
SwiGLU FFN6BNDF FLOPs; 3DF weightsThree dense projections
Materialized scores/probsO(BHN²) elementsOne N×N tensor per head


Compute/block (GELU) ≈ 8BND² + 4BN²D + 4BNDF
Weights/block (GELU) ≈ 4D² + 2DF


Memory example: B=4,H=32,N=4096 gives 4×32×4096²=2,147,483,648 attention-score elements. At 2 bytes each, that is about 4 GiB for one materialized attention-score tensor per block (before accounting for softmax copies, gradients, activations, and allocations). This illustrative memory footprint is why O(N²) intermediates can be a blocker.


FlashAttention nuance: IO-aware tiled attention can compute mathematically equivalent dense attention while avoiding materialization of the full score/probability matrices in HBM. It reduces memory traffic and the dominant attention intermediate-memory footprint, not the fundamental count of pairwise dot products in dense full attention. Sliding-window/sparse attention changes the actual interaction pattern and potentially arithmetic.


KV cache: after prefill, incremental decoding at one step attends one new query to N existing keys, giving attention work roughly O(BND) per new token per layer rather than recomputing N×N for old tokens. Per-layer KV elements are 2BNH_kv dₕ; multiply by layers and bytes/element for cache allocation. Heads for K/V may differ from Q heads in GQA.


What model size means: block weights plus embeddings and output head (tied or untied), biases/norms, and optional router/experts give model parameter totals. Parameter bytes + KV bytes + runtime/activation overhead must fit accelerator memory. Real latency also reflects batch scheduling, bandwidth, layout, and kernel choice, not FLOPs alone.
C Interview-ready spoken answer
For a dense Transformer block, QKV and output projections cost roughly 8BND² FLOPs, full attention two matrix products cost about 4BN²D, and a standard two-matrix FFN costs about 4BNDF. Materializing attention probabilities needs O(BHN²) elements, but fused attention kernels can avoid that allocation without changing dense-attention quadratic arithmetic. I separate weights, temporary activations, and KV cache when estimating memory or diagnosing long-context OOMs.
D Follow-up pressure test
  1. Compute the FP16 score tensor memory for B=4,H=32,N=4096. Strong response: 2,147,483,648 elements ×2 bytes=4 GiB per tensor.
  2. When does a fused attention kernel make full attention linear? Strong response: never in general dense pairwise arithmetic; it can improve IO and memory.
  3. What happens when N doubles? Strong response: projection and FFN work 2×, dense score/value mixing 4×, score tensor memory 4×.
Answer by explaining the mechanism, the trade-off, and how you would test the claim.
E Production scenario
Incident: A long-context serving change triggers CUDA OOM, yet model weights alone fit in GPU memory. Instrument: per-block peak allocation, prompt-length distribution, attention-kernel dispatch, KV occupancy, batch sizes, and memory fragmentation. Hypotheses: fallback to materialized-score kernel, doubled N, oversized concurrency/KV allocations. Acceptance: zero OOM on stress-test matrix; measured p95 TTFT/throughput and no attention-output or quality regression beyond defined tolerances.
F Interview takeaways
  • FLOPs ≈ 8BND² + 4BN²D + 4BNDF for standard GELU block.
  • Materialized attention probabilities scale as BHN²; fused kernels avoid storage, not dense math.
  • Separate weights, activation peaks, and KV cache in GPU-memory budgets.

A complete working educational model with fused scaled-dot-product attention, SwiGLU, learned absolute positions, causal isolation tests, and next-token loss. Requires PyTorch 2.x; CPU is sufficient. This HTML itself runs offline; the PyTorch code runs separately after download/copy.

"""Module 3 reference: a small pre-norm causal decoder-only Transformer.
Run: python module3_pytorch_reference.py
Requires: PyTorch 2.x (CPU sufficient).
"""
import torch
from torch import nn
from torch.nn import functional as F


class RMSNorm(nn.Module):
    def __init__(self, dim: int, eps: float = 1e-6):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        # Accumulate variance in FP32 for stability, return input dtype.
        rms = x.float().square().mean(dim=-1, keepdim=True).add(self.eps).rsqrt()
        return (x.float() * rms * self.weight.float()).to(x.dtype)


class CausalSelfAttention(nn.Module):
    def __init__(self, dim: int, n_heads: int, dropout: float = 0.0):
        super().__init__()
        assert dim % n_heads == 0, "hidden dimension must be divisible by heads"
        self.n_heads = n_heads
        self.head_dim = dim // n_heads
        self.qkv = nn.Linear(dim, 3 * dim, bias=False)
        self.out = nn.Linear(dim, dim, bias=False)
        self.dropout = dropout

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        B, T, D = x.shape
        # [B,T,3D] -> three [B,H,T,d_head] projections.
        q, k, v = self.qkv(x).chunk(3, dim=-1)
        def split(t):
            return t.reshape(B, T, self.n_heads, self.head_dim).transpose(1, 2)
        q, k, v = split(q), split(k), split(v)
        a = F.scaled_dot_product_attention(
            q, k, v, is_causal=True,
            dropout_p=self.dropout if self.training else 0.0,
        )  # [B,H,T,d_head]; causal attention, fused backend when available
        a = a.transpose(1, 2).contiguous().reshape(B, T, D)
        return self.out(a)


class SwiGLU(nn.Module):
    def __init__(self, dim: int, hidden: int):
        super().__init__()
        self.gate = nn.Linear(dim, hidden, bias=False)
        self.up = nn.Linear(dim, hidden, bias=False)
        self.down = nn.Linear(hidden, dim, bias=False)

    def forward(self, x):
        return self.down(F.silu(self.gate(x)) * self.up(x))


class DecoderBlock(nn.Module):
    def __init__(self, dim: int, n_heads: int, ff_hidden: int, dropout: float):
        super().__init__()
        self.norm1 = RMSNorm(dim)
        self.attn = CausalSelfAttention(dim, n_heads, dropout)
        self.norm2 = RMSNorm(dim)
        self.ffn = SwiGLU(dim, ff_hidden)

    def forward(self, x):
        x = x + self.attn(self.norm1(x))   # pre-norm, residual branch 1
        x = x + self.ffn(self.norm2(x))    # pre-norm, residual branch 2
        return x


class TinyDecoderLM(nn.Module):
    def __init__(self, vocab=128, max_context=64, dim=64, heads=4,
                 layers=2, ff_hidden=128, dropout=0.0):
        super().__init__()
        self.max_context = max_context
        self.token_emb = nn.Embedding(vocab, dim)
        self.position_emb = nn.Embedding(max_context, dim)
        self.blocks = nn.ModuleList([
            DecoderBlock(dim, heads, ff_hidden, dropout) for _ in range(layers)
        ])
        self.final_norm = RMSNorm(dim)
        self.lm_head = nn.Linear(dim, vocab, bias=False)
        # Tie token embedding and output head weights.
        self.lm_head.weight = self.token_emb.weight

    def forward(self, ids: torch.Tensor) -> torch.Tensor:
        B, T = ids.shape
        if T > self.max_context:
            raise ValueError('context window exceeded')
        positions = torch.arange(T, device=ids.device)
        x = self.token_emb(ids) + self.position_emb(positions)[None, :, :]
        for block in self.blocks:
            x = block(x)
        return self.lm_head(self.final_norm(x))  # [B,T,V]


if __name__ == '__main__':
    torch.manual_seed(7)
    model = TinyDecoderLM()
    model.eval()
    ids = torch.randint(0, 128, (2, 12))
    with torch.no_grad():
        logits = model(ids)
        changed = ids.clone()
        changed[:, 8:] = torch.randint(0, 128, changed[:, 8:].shape)
        changed_logits = model(changed)
    assert logits.shape == (2, 12, 128)
    # Future tokens cannot affect logits at earlier positions.
    torch.testing.assert_close(logits[:, :8], changed_logits[:, :8], atol=1e-5, rtol=1e-5)

    model.train()
    logits = model(ids)
    loss = F.cross_entropy(logits[:, :-1].reshape(-1, 128), ids[:, 1:].reshape(-1))
    loss.backward()
    assert model.blocks[0].attn.qkv.weight.grad is not None
    assert torch.isfinite(model.blocks[0].attn.qkv.weight.grad).all()
    print('shape:', tuple(logits.shape), 'loss:', round(loss.item(), 4))
    print('causality: passed | gradients: passed')
